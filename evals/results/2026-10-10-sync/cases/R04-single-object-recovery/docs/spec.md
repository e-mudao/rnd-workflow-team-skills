# 当前验收规格
来源：已确认 docs/brief.md；本规格由受托负责人 Lin 维护。docs/design.md 是 Chen 的建议，原文只读，不作为已确认行为。规格交付范围止于以下目标与待决项。

| ID | 条件与动作 | 可观察结果/失败条件 |
|---|---|---|
| AC-1 | 单文档，身份已被可靠验证，非未知且非模态，执行关闭 | 关闭能力可用且目标是已验证对象；不得以缺少第二窗口永久排除单文档。具体可靠关联路径待决 |
| AC-2 | 多文档（含标题无法区分的对象），身份已可靠验证，非未知且非模态，执行关闭 | 仅控制已验证目标；禁止仅凭标题或同名猜测对象 |
| AC-3 | 身份未验证、焦点/对象状态未知或处于模态时请求控制 | 拒绝控制，不操作未确认目标。拒绝原因解除且重新证实对象身份与安全状态后，允许恢复合法控制；若仍未知，继续拒绝。拒绝如何呈现在界面上待产品决定 |
| AC-4 | 单文档或多文档关闭过程中出现保存提示，用户取消 | 文档保留，用户能够继续工作；取消本身不证明对象已重新安全。不得以重新启动成功证明同一实例的恢复能力。恢复的具体触发、浮条表现及是否要求自动恢复见待决问题 |

边界：A→B真实焦点切换只是当前设计建议，不升级为所有情形的验收前提；单文档无 B，必须解决可达性。保存提示隐藏及取消后浮条自动恢复尚未被 brief 逐项确认，不擅自补成硬性验收。未知或模态的安全拒绝要求已经确认，无需再次询问。

## 待有权产品决定者回答的具体问题
1. 单文档首次绑定允许采用什么可验证的关联路径？需要用户执行什么动作，什么证据足以启用关闭？需与 Chen 确认设计可行性，禁止标题猜测约束保持。
2. 模态/未知状态拒绝控制时，浮条应如何表现，如何让用户获知拒绝原因？Chen 建议隐藏尚未确认。
3. “取消保存后继续工作”是否要求同一运行实例自动恢复浮条和关闭能力？恢复由何事件触发、是否允许额外用户动作、何时判失败？重启不作为同实例恢复证明。

待上述决定后 Lin 只在本规格补充可判定结果，再交后续计划；Chen 维护设计正文。已确认安全与单/多文档目标可直接作为依据，但依赖未决关联和恢复交互的实施与最终验收暂不能冻结。
