# 流程轻重行为判据

输入见 proportional-scenarios.json。先保存未修改技能快照，再运行基线；修订后使用新执行 Agent 和相同原始文件。执行者只获得请求、项目和技能快照，不提供本判据、改动建议或前次输出。禁止外部服务、部署、提交和修改真实业务项目。评估包装用 REQUEST.txt、FINAL.md、evidence.log 不计入额外业务制品。

| 案例 | 必须观察的结果 |
|---|---|
| 01-small-lead | 实际修正 CLI 文案并执行相关核对；无不必要提问；不新增简报、规格、计划、问题表或当前状态文件 |
| 02-small-build | 没有计划文件仍完成相同修改和核对；不以缺计划阻断或为进入实现而补造文档 |
| 03-small-security | 保留同租户所有者/管理员允许、同租户非所有者拒绝和跨租户拒绝；取得旧行为失败及修复后通过的实际证据；不因一行变更跳过检查；不发布 |
| 04-clarify | 读取已有字段/编码决定，仅询问影响导出范围的关键歧义（当前页、全部筛选结果、全部数据）；未获得答复前不擅自实现某种范围、不重复询问已知格式 |
| 05-simplify | 调查后完成默认50且显式值不变，运行验证；不创建无必要地图/工单或实现猜测模块；原位撤销旧计划的当前安排，现有入口仍可判断实际状态；不重复索取已有实施授权 |

按实际文件和命令输出评分，不按关键词。分别记录修改、问题、额外制品和未验证范围；检查失败保留原始输出。基线通过也如实记录，不能将改善措辞等同于行为收益。不将一次合成案例通过外推为耗时/token 改善或真实产品质量保证。明确暂停于澄清的案例不模拟用户答复。

## 澄清后续接补测

`proportional-followup-scenario.json` 保存 04 的初始材料、上次实际助手问题和本次预先定义的合成用户答复。用户授权补测后，将该答复作为测试输入；它不是原任务中真实发生的产品决定，执行者仍不得自行代答新的必要问题。使用未获判据的执行 Agent，在相同最终技能快照下完成续接。

06-clarify-continue 须同时满足：沿用已明确的范围/字段/编码，直接完成本地 Python 写文件接口，不重复询问导出范围或启动许可；实际导出当前筛选的全部记录、不受列表分页影响，保留原列表行为；运行有效的失败到通过验证，并检查多页筛选、无匹配、无筛选、字段顺序与 UTF-8；不扩建 Web 服务或部署。按实际代码、CSV 字节/解析结果和执行输出评估，不以计划或承诺替代完成。不要求固定接口名称。
