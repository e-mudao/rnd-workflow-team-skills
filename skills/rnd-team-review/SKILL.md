# 审查当前事实

按阶段读取当前原始输入：简报看目标与来源；规格看行为/判据；计划看依赖、方法和覆盖；实验看数据、方法、输出与分析；实现/集成看 diff、代码、合同及检查。负责审查记录，不覆盖被审内容。尚无代码时可审文档，不要求为了审查先实现。

## 多人任务边界

审查记录注明任务、含基线的完整 diff/版本、具体实现者与审查者，逐条问题返回实际维护人再注明责任角色。成员任务审查与集成候选审查分清范围；被审版本变化后复验受影响部分，不把另一成员的身份自动当成独立审查证明。

[接手、分工与交接字段](references/workflow.md) 使用项目现有记录；只有本地草稿时不声称已通知或同步给其他成员。

## 本次范围与证据

核对拒绝/隐藏是否同时定义触发、解除、合法恢复与可观察结果，按范围覆盖模态取消及同实例恢复；重启成功不能替代。检查未确认设计建议是否被写成硬性验收，完整行为参数是否被复制到计划/核验。核对关键反例是否先于依赖实现及推广；新支持范围不倒推为原始遗漏。

区分新接口编译 RED 与旧缺陷行为 RED/真实复现及修后复验，不以测试数量或编译通过替代覆盖。人工反馈核对实际运行轮次，不能移用到另一个候选或将成员结果提升为整体完成。

## 方法

1. 对照需求查漏项与越界，检查正确性、数据完整性、边界和错误路径、兼容性、安全、可维护性及有效测试。
2. 每条发现给出文件定位、触发条件、实际影响、严重度、建议和责任作者。缺上下文或未检查的范围明确列出。
3. 先依据原始文件形成判断，再参考实施者解释。同会话自审明确标记为非独立；真正独立审查须说明审查者、输入和上下文隔离依据。只有需要且获授权时才委派。
4. 在项目现有审查记录或任务章节保存范围、被审版本、发现、未解决项。作者修复后复验具体问题，保留前后结果。当前原始反证确立误报时，由审查记录现行维护人记录版本、误报原因和反证位置，保留原发现及历史，撤销发现和当前修复安排；争议或反证缺失时保持开放。

## 核验与返回

检查三件事：REV-1 审查输入与当前被审产物/阶段一致；REV-2 所需独立性有事实依据；REV-3 发现已处理并有适用复验。记录实际满足情况，按任务风险决定哪些是必需项。

发现 ID 绑定报告/版本，未关闭问题依 [责任映射](references/workflow.md) 交实际维护人及职责。本人完整目标内由 lead 接回责任方法修复受托内容，再回本角色对具体问题复验；其他维护人的真实缺陷仅交接并保持开放。误报撤销只修正本人维护的审查记录，不授予修改他人实现/规格的权限，不能凭实施者转述撤销。只审查请求以当前发现、撤销依据和复验建议交付，不能代修或重跑被审实验。满足当前审查要求后交 verify；未运行检查不能写成全部通过。

方法改编自 Superpowers 和 agent-skills 的需求符合性、质量、测试审查与按影响分级，见 [固定来源](references/methods.md)。
