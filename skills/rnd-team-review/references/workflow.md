# 多人协作、责任与证据约定

使用项目现有文档、任务表、Issue/PR、Git 与 CI。角色是职责，维护人是具体的人；Agent 在该人的授权范围工作。一人可承担多个职责，无需 11 个成员或新协作系统。

## 按目标选择工作

先看目标、未知项、影响、可恢复性和规模，再选必要职责；技术类型主要决定证明方式。明确且低风险的本人受托工作可直接依据请求与相关现有事实实施，不为满足角色输入补造简报、规格、验收编号或计划；小 diff 不等于低风险。已有适用计划、项目强制要求、用户指定文档、授权与证据规则仍有效。文档请求止于文档。迁移/重开发先区分旧事实与决定保留、改造、舍弃的需求，旧缺陷不自动升为新需求；保持行为的重构先明确基线和接口。调研围绕问题、方法、执行、分析组织，不预设必须成功或开发产品。使用项目已有工具、领域方法与专项技能，不宣称覆盖所有专业核验。

先读相关代码、文档和既有决定，只澄清会改变行为、成功标准或授权范围的未知项；信息充分即接续实施。调查消除复杂性时，由现行计划维护人在原处缩减未执行安排，保留必要决定、依赖和检查；其他成员提交具体建议，不宣称共享计划已改变。

## 接手与阶段接续

先核对当前项目、共享依据、本人的分配、分支与已有修改。每份共享制品或不重叠章节有一名现行维护人。调用 lead 不授予全项目指挥权。

| 接手信息 | 需要说明什么 |
|---|---|
| 任务与负责人 | 任务 ID/范围、本人实际负责人；协调、规格和集成负责人引用当前分工 |
| 依据 | 当前需求/规格的版本或章节、已有验收 ID（如有）、相关接口 |
| 工作范围 | 可改文件/模块/章节、独立分支及 checkout/工作树、共享或重叠点 |
| 依赖与状态 | 前置任务、合同是否确定、实际状态及阻塞原因 |
| 交接结果 | 接收人、可取得的准确提交或完整未提交交接包、真实检查、剩余项与下一动作 |

字段可合并在现有任务记录，不要求新文件或机器格式。用户明确分配可作为依据；与当前共享分工冲突时交协调者，继续已授权且不重叠部分。只有旧本地表时提出认领建议，不写成团队已接受的排他分配。本地分支任务表及会话摘要不等于最新共享状态。

由 lead 在本人完整任务内调用时，角色返回**产物位置、实际结果、未解决项、建议下一动作**。下一职责仍在本人分配及授权范围内，由当前 Agent 读取方法并继续，用过程消息报告，不让用户人工串联技能。涉及他人制品时交实际维护人及职责；不能靠切换角色代做。直接调用单角色按本次范围交付，已有完整目标仍有效时遵循实际停止点。仅审查或“计划后停止”等限制优先。

协调者依据团队确认维护共享分工；成员把建议交记录维护人整合。外部消息、Issue、推送和受控动作使用已有授权；否则准备本地草稿，不声称已通知、已接受或同步。技能不提供认领锁或自动通信。

## 人工检查点与恢复

- 依据实际未知项、影响、恢复成本、验证依赖及是否需要分批可靠交付判断任务规模。涉及多个文件/模块/函数只是线索，不单独触发人工检查点。范围和分工清楚、局部可逆且能一批验证的迁移或重构，在现有任务授权内直接接续，无需额外声明连续执行。确需分批可靠交付或有多项重要取舍的较大任务，首次既无批次约定、也无明确连续执行偏好时，先完成可独立调查与适用检查，交付目标、首个可验收范围、审查与检查点建议，等待**有权决定该事项的人**答复，再进入依赖实施。
- 沿用现有批次、停止点和连续授权；用户指定停止点优先。未决重大范围、公共接口或恢复成本明显的决定，交付具体变化、影响及建议后取得必要决定。普通角色切换、未约定停止点的分组、授权内修复复验不重复询问。
- 到达约定边界，报告任务、产物版本/范围、实际结果、开放问题和建议下一批。沉默、时间经过、文档齐全、review 通过或无该事项决定权者的同意都不能代替答复。确认权依现行分工和已有委托核对，不默认所有事项都归协调者或集成者。
- 确认绑定说明的任务、版本、内容与范围；部分确认仅推进子集，其余待答。Agent 提议实质改变已确认决定时再取得必要决定。用户明确调整按实际指令落实，含糊处澄清，普通排版不重批。

恢复时先读本人现有任务索引，核对当前源码/候选、权威依据、授权/停止点、证据、开放问题及下一动作。涉及检查点另记待答建议及版本/范围、实际确认版本/子集、有权决定者及答复依据（消息位置或忠实简短原意）。待答仍待答，部分确认只做子集，已确认不重问；旧下一动作不构成授权。缺依据先查现有记录，仍不明再集中澄清。共享索引只由现行维护人整合；成员的本地恢复记录标明实际同步状态。

## 当前状态与人工验收轮次

需要恢复或交接时维护已有状态入口；本次影响的既有摘要和问题项仍须更新，不因任务小遗留过期结论。不为无需恢复的一次性小修新建索引。本人维护的唯一当前摘要/问题表原位更新；旧“当前、待答、未关闭”入口改为当前引用或明确历史，写后回读确认。共享记录由现行维护人整合，其他成员提交具体修改建议，记录仍未同步，不把本地完成当共享完成。

人工验收每轮绑定任务、实际运行候选身份、应用、样本、窗口模式和动作，分别列出源码、新构建、成员/集成候选与实际运行实例。短答“成功”仅适用于已绑定轮次，不推广到新构建、其他应用或集成版本；缺绑定先核对，不猜测。待答轮次的新构建可能覆盖候选时，由有权维护该候选的人保存并核对可恢复产物及读取位置；不得擅自替换其他成员正在验收的实例。成员只能在受托范围操作，越界时交维护人，继续独立工作。

完整行为和参数只保留在现行权威规格；计划引用验收并安排实现及证明，核验记录证据与结论，lead 维护状态入口。没有正式规格的低风险工作以明确请求及现有事实作为依据，不为此补造文档。修正由各制品实际维护人完成，不靠切换角色越权。

## 并行工作与共享变更

并行写入使用独立分支及独立 checkout/工作树；不同分支名共用同一目录不能隔离编辑。同文件/章节由明确维护人串行整合。没有隔离能力时串行写入，其他成员可做只读或无重叠工作。写前重读，保留用户及其他成员已有修改。

运行服务或测试前，按项目现有开发环境约定核对并分配端口、测试数据库、输出目录及可变测试数据，记录本人使用的资源与归属。独立 worktree 只隔离源码，不自动隔离运行资源；不得连接到其他成员的服务、清空其测试数据或覆盖其输出。无法隔离的共享资源由现行维护人协调串行使用，确认可用后再执行相关命令；仅阻塞依赖该资源的运行，继续不受影响的工作。

超出边界的必要修改说明影响和建议负责人。共享接口、迁移、公共组件、配置或依赖变更说明现行合同、拟议变化、受影响任务、兼容和检查安排，交对应维护人纳入权威规格/计划；依赖未明时只阻塞相关部分。架构/设计建议先进入现行依据，再由分配的作者实施。查真实 diff，不能整文件覆盖语义冲突或把他人的工作算成本人完成。

## 失败责任与闭环

先给**实际任务/制品维护人，再注明职责**；没有维护人由协调者补分工，未知根因先调查，混合问题拆开。

| 问题 | 负责职责 |
|---|---|
| RTN-1：规格或验收 | rnd-team-spec |
| RTN-2：接口安排、依赖、计划、检查安排 | rnd-team-plan |
| RTN-3：实现或计划内测试遗漏 | rnd-team-build |
| RTN-4：目标、用户、范围、成功标准 | rnd-team-discover |
| RTN-5：风险或影响判断 | rnd-team-lead |
| RTN-6：架构或数据模型 | rnd-team-architecture |
| RTN-7：安全发现、覆盖或复验 | rnd-team-security |
| 实验问题、假设、范围、结果分析；结论超出证据 | rnd-team-discover |
| 实验可观察成功标准或指标 | rnd-team-spec |
| 实验方法、数据/样本、对照与安排 | rnd-team-plan |
| 实验脚本、配置、原始输出与执行事实 | rnd-team-build |

设计、审查记录、核验记录的问题分别交其 rnd-team-design、review、verify 当前维护人。同一人可切换职责，不能在未分配制品上自任作者。方法变动补受影响计算，历史输出保留；分析依据实际结果，不能改事实迎合结论。仅审查不授权修复、重跑被审实验或开发产品。

发现 ID 绑定报告/被审版本，修复前重读相关当前内容。本人完整任务内：确认发现 → 按职责修复受托内容 → 对具体问题复验 → 更新现行问题、索引及交接；保留历史失败，关闭项撤销当前修复安排，重开须有当前反例。确认属于其他维护人的真实缺陷，只交接并保持开放，待作者修复及适用复验后关闭。

当前原始反证确立发现为误报时，由审查记录现行维护人撤销该发现：记录核对版本、误报原因与反证位置，保留原发现及历史，撤销其当前修复安排并更新现行问题/交接。争议未决或反证缺失时保持开放，不能凭实施者转述撤销。撤销误报只修正本人维护的审查记录，不授予修改他人实现或规格的权限。

## 交接与集成

成员说明当前任务实现范围、准确版本/diff、真实检查、合同偏差与剩余项，状态为待审/待集成或项目等价状态，成员完成不等于团队功能完成。

优先交付接收者可取得的完整提交 ID，并注明仓库/分支或制品读取位置。采用未提交交接时，交接记录包含：基线提交 ID、覆盖暂存区与工作区的完整补丁、任务所需新增/未跟踪文件及二进制内容、可读取位置、交付文件清单与内容摘要（或等价快照身份）。普通 `git diff` 不包含暂存区和未跟踪文件，不能单独代表完整候选。只打包任务所需内容，排除凭证、无关修改和缓存；无 Git 时提供完整任务快照、清单及读取位置。接收者先在隔离目录核对基线、还原交付并检查清单/摘要与证据对应的候选一致，再进行集成；材料不完整时保持待补交接，不声称已接收准确版本。

指定集成者按依赖核对接收版本和合同，在授权范围内合并；语义冲突交有关实现/规格维护人澄清后整合。PR、分支保护、独立审查沿用项目要求，合并不代表部署授权。

最终核验绑定准确集成版本与工作树状态，检查任务验收、真实模块交互、受影响回归及必要 CI/审查；分支分别绿色不能相加成整体绿色，mock 与真实合同须核对。集成失败返回实际维护人及职责，接收准确修复版本，再在新的集成版本补受影响检查；旧集成通过不覆盖新失败。可先只读审查候选，未运行部分标未验证。

## 真实证据与增量复用

记录准确版本/相关文件和未提交修改、命令、cwd、退出码、完整输出/截图位置、影响结果的工具版本/配置/数据/目标环境；未知项直说，不记录秘密。文档合并引用具体章节，精确核对时用现有工具计算字节摘要，不编造值。

核验先绑定当前任务和权威验收，明确低风险且无正式验收时逐请求要求核对，不补造 AC ID；提示词示例与当前项目不符时澄清，不造新验收。当前相关输入、方法与环境未变时可复用证据，注明覆盖范围；合并交互和其他受影响检查补到集成版本。缺项、中断、未运行、模拟、自审如实区分，另一会话/成员不自动保证独立。文档完整或编译成功不等于业务通过。

## 分批与上下文

按可独立检查的功能/研究结果分批，不按技能、文件或固定任务数机械拆分。先读索引、目录、入口，再读本次相关输入；当前会话加载且未变的共同约定/来源可复用，版本变化或上下文丢失后按需恢复。完整日志留文件，只带当前结果。需要恢复/交接时更新本人现有索引，本次影响的既有状态和问题入口同步修正；跨批上下文不同、难恢复或用户希望时准备简短交接并建议换会话，不自动另开任务、不假造 token 门槛。人工检查点、职责切换与会话切换分别安排。

## 发布与授权

明确准备还是执行、指定执行人、动作、候选、目标环境与实际权限。准备者不替执行人部署，分工不替代动作授权。权限/技能/工具/独立审查或外部依赖缺失时说明阻断范围，只继续不依赖它的已授权工作，不能绕过停止点。并发发布或结果未知时由已授权人先调查，不盲目重放。技能不提供身份认证、写锁或授权消费服务，日常开发无需自建这些服务。
