# 多人研发入口

每个成员从这里接手自己的任务，Agent 在本人受托范围自动选择方法、接续和修复复验。读取 [协作约定](references/workflow.md)。明确被分配为协调或集成者时才承担相应职责；调用入口不授予全项目指挥权。

## 执行循环

1. **恢复本人目标。** 核对实际项目、任务 ID、本人分配、权威规格/计划、当前文件和已有修改、相关接口、独立工作目录、最新证据及未完成项。检查待答、确认版本/子集、有权决定该事项的人及答复依据；旧下一动作不能代替确认。

   本会话首次使用共同协作约定时完整读取 [协作约定](references/workflow.md)；后续职责切换中内容未变且上下文仍可用时复用，不因切换职责重复读取。复用只减免重复读取，不替代对权威规格、任务记录与当前事实的核对；相关内容变化、上下文丢失或无法确认版本时，重新读取必要内容。任务与项目不对应时集中澄清，不能凭示例造验收。记录冲突交协调者，继续已授权且不重叠的部分。
2. **选择必要工作。** 按目标、实际未知项、影响、恢复成本、验证依赖及分批交付需要选择职责；技术类型决定证明方式。多文件/多函数不单独触发检查点，明确、局部可逆且可一批验证的迁移/重构在现有任务授权内直接接续，无需额外连续执行声明。小修不强制完整文档链，单次审查/计划/调研止于请求范围。确需分批可靠交付或有多项重要取舍的较大任务，首次既无批次约定、也无明确连续执行偏好时，先调查、完成适用质量检查，给出首个可验收范围与检查点建议，等待有权决定者答复再进入依赖实施。已有约定及停止点优先。
3. **接回阶段结果。** 接收产物位置与准确版本、实际结果、未解决项、建议下一动作、待答问题及有权决定该事项的人。缺项先查证；确实未知则标明未知，不推测填充；无待答事项写"无"；本次为澄清或分析结果、没有文件产物时写"本次答复"，不为满足字段另造文件。下一工作仍属本人分配且已授权时，读取相应技能并继续，用过程消息说明进展；无需用户逐个调用技能。涉及他人任务或制品时交实际维护人和职责，留下本地草稿或依已有授权实际交接，不代做、不假定已接收。

   相同问题、候选与证据经多轮仍无实质进展时，先调查阻因；确有依赖或权限阻断再交付恢复动作。有进展的授权内修复继续，不因轮次停工。

   缺少角色能力，或缺失信息影响候选确认、授权及下一步正确性时，只阻塞依赖部分；其他已授权且不受影响的工作继续。
4. **闭合本人问题。** 核对发现与当前版本，按责任方法修复本人受托内容，再返回审查具体复验，更新现行问题与下一动作。混合问题分开，其他维护人的真实缺陷保持开放并交接。当前原始反证确立误报时，审查记录维护人依协作约定记录版本、原因与证据，保留历史并撤销当前修复安排；争议或缺反证仍保持开放。仅审查请求只维护审查记录，不代修实现。行为/方法实质变化先由对应维护人更新依据并取得必要决定，不能放宽验收消除失败。同 Agent 自审/复验仍为非独立。
5. **维护当前索引。** 需要恢复或交接时沿用本人任务记录，本次影响的既有状态与问题项仍需更新；共享索引只由其现行维护人整合。保留目标/范围、源码与候选、证据、开放问题、接收人及下一动作，检查点再记建议/实际确认版本、子集、决定人和答复依据。按可验收结果分批，按需读取入口/相关材料；换会话需要时准备简短交接，不自动创建会话或发消息。
6. **核对停止条件。** 本人请求完成、首批约定待答、约定检查点、未决重大选择或实际权限/依赖阻断时，交付具体结果和恢复动作。普通职责切换及没有约定停止点的分组继续循环；部分确认只推进子集，其他人的同意须有该事项决定权。停止点不能靠无关工作绕过，已授权普通修复不重复询问。

协调者维护确认过的分工与共享依据；集成者核对交付版本和依赖、处理实际冲突，在准确集成版本核验真实交互及受影响回归。两者也受自身分配和停止点约束。成员完成、待集成及整体核验分别报告。

## 本次范围与证据

明确低风险任务直接从请求及现有事实进入 build/verify，不补造前置文档或 AC 编号；已有适用计划仍执行。先读再问，信息足够即继续。调查后简化仅修改本人维护的未执行计划；共享计划交维护人。状态更新按协作约定原位修正并回读，按需维持恢复入口；人工反馈只归已绑定的运行候选轮次。

## 按需定位方法

路径相对**已加载的 rnd-team-lead 技能目录**，不是业务 cwd；也可用宿主公布的位置。下表是候选定位提示，不是硬性门槛：命中信号不等于必须进入该职责，无法判定归属时按 [协作约定](references/workflow.md) 处理——未知根因先调查；确认后交实际任务或制品维护人并注明职责；缺少维护人时由协调者补充分工。只读取当前需要的方法，缺失时说明具体技能，不宣称已执行或自行安装。

| 可观测信号 | 候选职责 | 方法路径 |
|---|---|---|
| 用户问题、范围、约束含糊，或需澄清用户目标与假设 | 发现 | `../rnd-team-discover/SKILL.md` |
| 调研问题、假设、范围或结果分析；结论是否超出证据 | 发现 | `../rnd-team-discover/SKILL.md` |
| 现行行为或判据不可判定、存在争议，需稳定验收 | 规格 | `../rnd-team-spec/SKILL.md` |
| 实验的可观察成功标准或指标未定义 | 规格 | `../rnd-team-spec/SKILL.md` |
| 任务未拆分；缺负责人、依赖、隔离目录或检查安排 | 计划 | `../rnd-team-plan/SKILL.md` |
| 实验方法、数据/样本、对照与安排 | 计划 | `../rnd-team-plan/SKILL.md` |
| 测试或构建失败 | 实现（**先调查归属**；可能来自环境、规格或他人变更，确属受托实现再进入） | `../rnd-team-build/SKILL.md` |
| 已确认需求或既有失败需要改动代码、脚本、配置 | 实现 | `../rnd-team-build/SKILL.md` |
| diff 已存在但未被检查；简报、规格、计划、实验或实现待审 | 审查 | `../rnd-team-review/SKILL.md` |
| 有人声明完成，需对照验收与真实证据 | 核验 | `../rnd-team-verify/SKILL.md` |
| 仅需发布**准备**（产物、配置、版本、健康检查、恢复准备） | 发布 | `../rnd-team-release/SKILL.md` |
| 已有发布**授权**并要求执行部署 | 发布（须核对动作、候选、环境与授权依据） | `../rnd-team-release/SKILL.md` |
| 发布结果未知或超时 | 发布（由已授权负责人先调查状态，不重放） | `../rnd-team-release/SKILL.md` |
| 共享接口、依赖或数据模型的取舍 | 架构 | `../rnd-team-architecture/SKILL.md` |
| 用户流程、布局、可访问性、渲染核对 | 界面 | `../rnd-team-design/SKILL.md` |
| 入口点、身份、授权点、敏感数据或攻击面 | 安全 | `../rnd-team-security/SKILL.md` |

缺失 AC 编号本身不触发规格工作；明确低风险任务沿用请求与现有事实核验。核验职责可核对发布就绪及授权事实，但不授予执行权限。

目标包含发布准备或授权部署时，先核对当前集成结果 → 指定执行人用 release 处理所请求的工作 → verify 核对对应完成层级。指定执行人不替代当前动作、候选及环境的实际授权；未知结果先调查。

## 交付

报告任务 ID、实际负责人、准确版本或符合协作约定的完整未提交交接包、改动、检查证据、完成层级、接收人、剩余项及恢复动作。来源见 [固定方法](references/methods.md)。使用项目现有文档、Git 与 CI，不要求运行时、身份认证、并发写锁或审批服务。
